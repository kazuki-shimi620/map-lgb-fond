# フロントエンド性能予算

## 目的

`frontend/public` 全体の容量ではなく、東京都の初回予測から周辺施設パネルを開くまでの
1セッションで実際に取得・展開する量と操作応答を監視する。ローカルPlaywrightの値は
回帰検知に使い、実機性能や本番回線の保証値にはしない。

## 2026-08-09 基準値

Vite production buildをローカルpreviewし、キャッシュなしで各1回計測した。

| 指標 | Desktop Chrome相当 | Pixel 7相当 | CI上限 |
|---|---:|---:|---:|
| 初回予測表示 | 4,523ms | 4,446ms | 12,000ms |
| 条件変更後の再予測 | 1,913ms | 1,931ms | 3,000ms |
| 周辺施設パネル表示 | 48ms | 63ms | 300ms |
| 同一origin転送量 | 31,727,558 bytes | 31,727,558 bytes | 40,000,000 bytes |
| 同一origin展開後容量 | 117,628,496 bytes | 117,628,496 bytes | 130,000,000 bytes |
| 地図ドラッグ中rAF | 59.1fps | 60.9fps | 記録のみ |
| JSヒープ概算 | 167MB | 157MB | 記録のみ |
| 最長long task | 3,081ms | 2,922ms | 記録のみ |

Pixel 7はPlaywrightのviewport・user agentエミュレーションであり、CPUやメモリ性能を
実機相当に制限しない。FPS、ヒープ、long taskはOS、ブラウザ、開発端末の影響が大きいため、
CIでは失敗条件にせず推移だけを見る。スマートフォン実機では低速回線、発熱後、メモリ圧迫時を
別途確認する。

## セッション内訳

初回セッションの主な展開後容量は、首都圏4モデル39,263,474 bytes、都市計画JSON
57,851,663 bytes、ONNX Runtime WASM 10,551,547 bytes、施設JSON 5,513,679 bytes、
価格履歴3,109,310 bytesである。

初期の東京都モデル読み込み後、待機時間に神奈川・埼玉・千葉モデルもプリフェッチするため、
モデル容量は東京都単体ではなく首都圏4都県分になる。モデルセッション自体はLRUで直近2地域に
制限するが、取得済みバイナリとは別管理である。

## 回帰検知

`frontend/e2e/performance.spec.ts` は初回・再予測時間、パネル応答、転送量、展開後容量、
施設CanvasをCIで検証する。FPS、ヒープ、long task、取得ファイル一覧もJSON attachmentへ
記録する。上限を変更する場合は、計測条件、変更理由、新旧値をこの文書へ残す。
