# モデル説明機能検討

本ドキュメントは、価格予測モデルの説明機能としてSHAPまたは代替指標を導入する方針を定義する。

## 目的

ユーザーが予測価格を見たときに、価格に影響した主な条件を理解できるようにする。

対象は次の2種類に分ける。

```text
モデル全体の説明: どの特徴量が全体として効いているか
個別予測の説明: いま入力した物件で何が価格を押し上げ、何が押し下げたか
```

既存UIの「特徴量重要度」はモデル全体の説明であり、個別予測の増減要因とは区別する。

## 方針

初期導入では、SHAP計算をブラウザには載せない。

理由:

* ONNX Runtime Webの推論結果からTreeSHAPの寄与度を直接取得できない
* ブラウザへLightGBM本体やSHAP実装を追加すると容量と初期化時間が増える
* ポートフォリオとして常時公開する用途では、予測の軽さと壊れにくさを優先する

学習側でLightGBMの寄与度を計算し、軽量な集計JSONとして出力する方式を第一候補にする。

## 採用候補

### 1. モデル全体の重要度

既存の `featureImportance` を継続利用する。

```text
feature
importance
```

メリット:

* すでにメタデータへ出力済み
* ブラウザ追加実装が小さい
* モデル比較時の確認に使える

制約:

* 個別物件の増減要因ではない
* カテゴリ特徴量や欠損フラグの解釈に注意が必要

### 2. 学習側でのSHAP集計

LightGBMの `pred_contrib` またはSHAP相当の計算を学習側で実行し、地域別・代表条件別の集計値を出力する。

出力例:

```json
{
  "region": "tokyo",
  "generatedAt": "2026-07-11T00:00:00Z",
  "topGlobalContributions": [
    { "feature": "station", "meanAbsContribution": 8200000 },
    { "feature": "area", "meanAbsContribution": 6400000 }
  ],
  "segments": [
    {
      "name": "駅徒歩10分以内",
      "conditions": { "maxWalkMinutes": 10 },
      "topContributions": [
        { "feature": "station_walk_minutes", "direction": "positive", "label": "駅徒歩が短い" }
      ]
    }
  ]
}
```

ブラウザでは、個別予測の厳密なSHAPではなく、入力条件に近い代表セグメントの説明を表示する。

メリット:

* ブラウザ配布サイズを抑えられる
* 学習時と同じPython環境で検証できる
* 地域別に説明の癖を確認できる

制約:

* 入力1件ごとの厳密な寄与度ではない
* セグメント設計を粗くしすぎると説明が一般論になる

### 3. ブラウザ内の簡易差分説明

入力条件を少し変えた場合の予測差分を表示する。

例:

```text
駅徒歩を8分から13分へ変えると -350万円
築年数を15年から20年へ変えると -420万円
```

メリット:

* 既存のONNX推論だけで実装できる
* ユーザーの入力に対して直感的

制約:

* 変数間の相互作用は説明しきれない
* 複数回推論するため、モバイルでは回数制限が必要

## 推奨MVP

以下の順で段階導入する。

1. 既存のモデル全体重要度を「モデル全体の特徴量重要度」と明示する
2. 学習側でSHAP集計JSONを出力し、地域別の上位寄与を確認する
3. UIでは代表セグメント説明または簡易差分説明だけを表示する
4. 個別予測の厳密SHAPは、容量・速度・保守性を見て後回しにする

## 出力先

学習側の成果物:

```text
training/outputs/explanations/
```

ブラウザ配信用に採用する場合:

```text
frontend/public/explanations/
```

初期は `frontend/public` へ自動配置せず、学習・比較レポートとして確認する。

## 検証観点

* 上位寄与が既知の不動産感覚と大きく矛盾しない
* 欠損フラグやデータ提供範囲フラグが上位を占めすぎない
* 商業施設、駅規模、ハザード特徴量が地域差だけを代理していない
* JSONサイズが地域ごとに数十KB程度へ収まる
* モバイルで追加通信しても初期表示を遅くしない

## 非目標

初期段階では次を行わない。

* ブラウザ上でTreeSHAPを完全再計算する
* 全取引データのSHAP値をブラウザへ配布する
* 説明値を査定根拠や価格保証として表示する
