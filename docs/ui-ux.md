# UI/UX設計書

# 不動産価格予測画面 UI/UX設計

## 1. 目的

価格予測画面は、ユーザーが物件条件を調整しながら予測価格と価格推移を素早く確認することを主目的とする。

商業施設、駅規模、災害リスク、モデル詳細は意思決定を補助する参考情報として扱い、主操作の視線移動を妨げない位置と密度に整理する。

## 2. 情報優先度

### 最優先

* 物件条件フォーム
* 予測年、将来シナリオ
* 予測価格、平米単価、参考価格帯
* 価格推移グラフ

### 補助情報

* 周辺商業施設
* 最寄駅の規模
* 災害リスク評価
* 条件、モデル評価、特徴量重要度

## 3. 画面の完成形

デスクトップでは、地図の下を2カラムに分ける。

左カラムは物件条件を入力し、直下で予測結果を確認する領域にする。

右カラムは予測年、将来シナリオ、価格推移をまとめる領域にする。予測年を変更した直後に価格推移グラフを見られるよう、価格推移は予測年カードのすぐ下に置く。

```text
+------------------------------------------------------------+
| 地図                                                       |
+------------------------------+-----------------------------+
| 物件条件フォーム             | 予測年・将来シナリオ        |
+------------------------------+-----------------------------+
| 予測結果                     | 価格推移                    |
+------------------------------+-----------------------------+
| 参考情報カード                                             |
| [商業施設] [駅規模] [災害リスク] [モデル]                  |
| 選択中タブの内容                                           |
+------------------------------------------------------------+
```

モバイルではボトムシート内で1カラムにし、順序は `入力フォーム → 予測年・シナリオ → 予測結果 → 価格推移 → 参考情報` とする。

## 4. レイアウト方針

物件条件フォームと予測設定は分離するが、予測設定は価格推移と同じ右カラムに置く。

予測結果はフォーム直下に置き、入力条件を変更した結果がすぐ分かるようにする。

価格推移は予測年カード直下に置き、将来シナリオや予測年を変更した結果が視線移動少なく確認できるようにする。

補助情報は複数カードを同時に2列表示せず、カード型のタブ付き参考情報エリアに集約する。これによりカードの高さ差や密度差による視覚的なばらつきを抑え、必要な詳細だけを表示する。

## 5. 参考情報タブ

参考情報エリアは以下のタブで構成する。

* 商業施設
* 駅規模
* 災害リスク
* モデル

初期表示は商業施設とする。タブはボタンとして実装し、選択中のタブを明確に示す。

参考情報エリア全体を1つのカードとして見せる。各タブの中身は同じカード内の本文として表示し、カードをカード内に入れ子にしない。

## 6. 詳細情報の省略

モデル詳細は常時展開カードとして下部に置かず、参考情報タブの「モデル」に移動する。

災害リスクや商業施設の長い説明文は、主画面の上部には出さず、該当タブを選択したときだけ表示する。

将来シナリオは横ばいと標準の意味が異なるため選択肢を維持する。説明は `i` アイコンのツールチップで補足する。

## 7. モバイル方針

モバイルではボトムシート内で以下の順に縦積みする。

```text
----------------------+
| 入力フォーム        |
+----------------------+
| 予測年・シナリオ    |
+----------------------+
| 予測結果            |
+----------------------+
| 価格推移            |
+----------------------+
| 参考情報タブ        |
+----------------------+
```

参考情報タブは横スクロール可能なボタン列とし、本文は1カードのみ表示する。

## 8. 実装メモ

* 参考情報タブは `SupportingInfoTabs` コンポーネントで管理する。
* タブ本文には既存の `CommercialFacilityCard`、`StationScaleCard`、`HazardRiskCard`、`PredictionDetailsPanel` を渡す。
* 参考情報タブ内では既存カードの外枠を抑制し、タブエリア全体を1枚のカードとして見せる。
* デスクトップでは `PriceHistoryChart` を `forecast-panel` の直下に配置する。
* デスクトップの主領域は、CSS Gridの同一行に各カードを直接並べず、左カラムと右カラムを独立した縦スタックとして実装する。これによりフォームの高さに右カラムが引っ張られて不自然な空白が生まれることを防ぐ。
* タブ切り替えはクライアント内状態のみで完結させる。
* ブラウザ推論、モデル成果物、学習処理には影響を与えない。

## 9. 参考情報カードの表示ルール

教育施設、用途地域、人口統計、犯罪統計を参考情報として追加する場合は、価格予測の断定材料ではなく、周辺環境を確認するための補助情報として表示する。

各カードには共通して以下を表示する。

* 見出し
* 対象地点または集計単位
* データ年度
* 出典
* 取得または生成日時
* 価格モデルへの採用状況

価格モデルへの採用状況は、次のいずれかの短い文言に統一する。

```text
参考表示のみ
モデル採用候補
モデル採用済み
検証保留
```

カード末尾には、必要に応じて次の注意書きを表示する。

```text
価格モデルへの採用とは分けた参考情報です。
```

```text
データ年度や集計単位が地域により異なる場合があります。
```

### 教育施設カード

表示目的は、子育て・通学利便性の確認に限定する。学校の良し悪しを評価する表現は使わない。

主な表示項目:

* 最寄小学校名と直線距離
* 最寄中学校名と直線距離
* 半径1km以内の保育園・幼稚園件数
* 半径1km以内の小学校・中学校件数
* データ年度
* 出典

文言例:

```text
周辺教育施設
最寄小学校 〇〇小学校 0.8km
最寄中学校 〇〇中学校 1.2km
半径1km以内 保育園・幼稚園 5件
```

### 用途地域カード

表示目的は、周辺の都市計画上の位置づけを確認することに限定する。住みやすさや資産性を断定しない。

主な表示項目:

* 用途地域
* 建ぺい率
* 容積率
* 区域区分
* 判定方法
* データ年度
* 出典

文言例:

```text
用途地域
第一種住居地域
建ぺい率 60%
容積率 200%
```

地点判定に失敗した場合は、古い値を残さず次の文言を表示する。

```text
この地点の用途地域データは未取得です。
```

### 人口統計カード

表示目的は、自治体単位または小地域単位の人口傾向を確認することに限定する。将来の人口増減を保証する表現は使わない。

主な表示項目:

* 集計単位
* 総人口
* 世帯数
* 人口密度
* 65歳以上人口比率
* 前回調査からの人口増減率
* データ年度
* 出典

文言例:

```text
人口統計
集計単位 千代田区
総人口 68,000人
世帯数 39,000世帯
人口増減率 +3.2%
```

### 犯罪統計カード

犯罪・治安指標は、印象評価や星評価にしない。件数、人口あたり件数、年度、出典、集計単位だけを表示する。

主な表示項目:

* 集計単位
* 刑法犯認知件数
* 人口1000人あたり刑法犯認知件数
* 前年比
* データ年度
* 出典

使わない表現:

```text
治安が良い
治安が悪い
安全
危険
おすすめ
星評価
```

文言例:

```text
犯罪統計
集計単位 千代田区
刑法犯認知件数 1,200件
人口1000人あたり 17.6件
```

## 初回利用の導線

主動線は `場所を選ぶ → 条件を入力 → 価格と理由を見る` の3段階とする。初回アクセス時は
地図やフォーム操作を遮らない非モーダル案内をヘッダー直下へ表示する。「わかりました」で閉じると
完了状態をLocalStorageへ保存し、次回以降は自動表示しない。

案内を閉じた後も、ヘッダーの「使い方」ボタンから再表示できる。LocalStorageが利用できない環境でも
案内は閉じられ、操作を妨げない。周辺施設・災害リスク・モデル詳細は従来どおり参考情報タブへ置き、
3段階の主動線には含めない。
