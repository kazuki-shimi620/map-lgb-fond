# frontend-e2e-test.md

# フロントエンドE2Eテスト仕様

本ドキュメントは、不動産価格予測アプリの主要なユーザー操作をPlaywrightで検証するための仕様を定義する。

対象は `frontend/` 配下のReactアプリケーションとし、Pythonの学習処理、前処理、ONNX変換処理自体は対象外とする。

---

# 1. 目的

以下をE2Eテストで確認する。

* アプリケーションが正常に起動する
* 初期データ、駅マスタ、価格推移、モデルを読み込める
* 地図と入力フォームを操作できる
* 入力変更に応じて価格予測が自動更新される
* 予測結果と価格推移グラフが表示される
* デスクトップとスマートフォンの主要レイアウトが崩れていない
* README掲載用スクリーンショットを再現可能な形で生成できる

---

# 2. 使用技術

```text
@playwright/test
```

# 5. テスト方針

## 5.1 通常E2EとREADME画像生成の分離

通常E2E:

```text
frontend/e2e/*.spec.ts
```

README画像生成:

```text
frontend/e2e/screenshots.spec.ts
```

通常テスト失敗時のスクリーンショットをREADME画像として流用しない。README画像は固定された入力値、画面サイズ、モック、待機条件で生成する。

## 5.2 外部通信

CIでは住所検索、逆ジオコーディング、将来のハザード評価APIなどの外部通信をモックする。

理由:

* 外部API停止でテストが不安定になる
* 通信速度で結果が変わる
* レート制限を避ける
* README画像を固定しやすくする

実サービスとの疎通確認は、手動または定期実行の別テストとして扱う。

## 5.3 モデルと静的データ

ONNXモデル、メタデータ、駅マスタ、価格推移JSONは、原則として配布用静的ファイルを使う。

CI実行時間やモデルサイズが問題になる場合は、次の2段階に分ける。

1. Pull Requestでは軽量なテスト用モデルを使う
2. mainブランチまたは手動実行では実モデルを使う

## 5.4 セレクタ

優先順位:

1. `getByRole`
2. `getByLabel`
3. `getByText`
4. `data-testid`
5. CSSクラス

地図、グラフ、ボトムシートのハンドルなど、roleで表現しにくい箇所だけ `data-testid` を使う。

推奨ID:

```text
data-testid="property-map"
data-testid="prediction-form"
data-testid="prediction-result"
data-testid="price-history-chart"
data-testid="prediction-sheet"
data-testid="sheet-handle"
```

# 7. テストケース

## 7.1 初期表示

### E2E-INIT-001 アプリケーションを表示できる

期待結果:

* ページタイトルが表示される
* 「不動産価格予測」が表示される
* 地図が表示される
* 物件条件フォームが表示される
* JavaScriptエラーが発生しない

### E2E-INIT-002 初期値が設定される

期待結果:

* 都道府県が東京都
* 市区町村が千代田区
* 最寄駅が東京
* 専有面積が55
* 築年数が15
* 駅徒歩が8
* 間取りが2LDK

### E2E-INIT-003 モデル読み込み状態を表示できる

期待結果:

* 読み込み中に「モデルを読み込んでいます」が表示される
* 読み込み完了後にローディング表示が消える
* 読み込み完了後に予測結果が表示される

## 7.2 自動価格予測

### E2E-PRED-001 初期条件で価格を予測できる

期待結果:

* 予測価格が表示される
* 平米単価が表示される
* 参考価格帯が表示される
* 価格推移グラフが表示される
* エラーが表示されない

### E2E-PRED-002 専有面積変更時に予測を自動更新する

操作:

1. 初期予測完了を待つ
2. 現在の予測価格を取得する
3. 専有面積を55㎡から70㎡へ変更する
4. 再予測完了を待つ

期待結果:

* 予測ボタンなしで再予測される
* 予測価格が更新される
* 入力値に70㎡が保持される
* グラフも更新される

### E2E-PRED-003 築年数変更時に予測を自動更新する

期待結果:

* 予測結果が更新される
* エラーが表示されない

### E2E-PRED-004 駅徒歩変更時に手入力値を使用する

期待結果:

* 手入力した駅徒歩がフォームに保持される
* 手入力値で再予測される

### E2E-PRED-005 都道府県変更時に地域モデルを切り替える

期待結果:

* 変更前の予測結果が一度クリアされる
* 対象地域のモデルが読み込まれる
* 対象地域の駅候補が表示される
* 新しい条件で予測結果が表示される

### E2E-PRED-006 長期予測時に警告を表示する

期待結果:

* 「長期予測のため精度は保証できません」が表示される

## 7.3 地図操作

### E2E-MAP-001 地図クリックで物件位置を変更できる

期待結果:

* 選択位置にマーカーが表示される
* 都道府県、市区町村、最寄駅、駅徒歩が更新される
* 新しい条件で予測される

### E2E-MAP-002 住所検索で地図を移動できる

期待結果:

* 地図の中心が検索地点付近へ移動する
* 検索だけでは物件位置が確定されない
* 地図クリック後に物件条件が更新される

### E2E-MAP-003 未対応位置を選択した場合に警告する

期待結果:

* 予測結果がクリアされる
* 未対応地域の警告が表示される
* 予測処理が実行されない

### E2E-MAP-004 逆ジオコーディング失敗時に手入力へ誘導する

期待結果:

* 地域または駅情報の取得失敗メッセージが表示される
* フォームを手入力できる

## 7.4 価格推移グラフ

### E2E-CHART-001 価格推移グラフを表示できる

期待結果:

* グラフ領域が表示される
* 対象駅名が表示される
* 過去価格または推計値が表示される
* 将来予測値が表示される
* ラベルが画面外へ見切れない

### E2E-CHART-002 過去データを追加表示できる

期待結果:

* 2020年以前のデータが追加される
* グラフの表示期間が広がる
* ローディング中の二重実行が発生しない

### E2E-CHART-003 過去データを閉じられる

期待結果:

* 2020年以降の表示へ戻る
* 将来予測値は保持される

## 7.5 レスポンシブ表示

### E2E-RESP-001 デスクトップで2ペイン表示になる

画面サイズ:

```text
1440 x 900
```

期待結果:

* 地図とフォームが同時に表示される
* フォームが地図へ不自然に重ならない
* 入力フォーム、予測結果、価格推移をこの順で確認できる
* 災害リスク評価と条件・モデル詳細は価格推移より下に表示される

### E2E-RESP-002 スマートフォンでボトムシートを表示できる

期待結果:

* 地図が画面上部に表示される
* フォームがボトムシートとして表示される
* 初期状態で地図操作を妨げない
* ボトムシート内をスクロールできる

### E2E-RESP-003 地図選択後にボトムシートが中間位置になる

期待結果:

* ボトムシートが中間位置へ移動する
* 地図上の選択位置を確認できる
* 更新されたフォーム値を確認できる

### E2E-RESP-004 ボトムシートを全画面表示できる

期待結果:

* ボトムシートが全画面相当まで開く
* 予測結果と価格推移までスクロールできる
* 災害リスク評価と条件・モデル詳細は主動線の後に確認できる
* 横方向にはみ出さない

## 7.6 エラー処理

### E2E-ERR-001 モデル読み込み失敗時にエラーを表示する

期待結果:

* 「モデルの読み込みに失敗しました」が表示される
* 不完全な予測結果が表示されない

### E2E-ERR-002 駅マスタ読み込み失敗時にエラーを表示する

期待結果:

* 「駅マスタまたは価格推移データを読み込めませんでした」が表示される

### E2E-ERR-003 価格予測失敗時にエラーを表示する

期待結果:

* 「価格予測に失敗しました」が表示される
* 以前の不正確な予測結果を表示し続けない

# 9. 実行コマンド

`frontend/package.json` に追加する。

```json
{
  "scripts": {
    "test:e2e": "playwright test",
    "test:e2e:ui": "playwright test --ui",
    "test:e2e:headed": "playwright test --headed",
    "test:e2e:report": "playwright show-report",
    "test:e2e:screenshots": "playwright test e2e/screenshots.spec.ts --project=chromium"
  }
}
```

初回セットアップ:

```bash
cd frontend
npm install
npx playwright install
```

CIでは必要なブラウザだけをインストールする。

```bash
npx playwright install --with-deps chromium
```

# 10. CI方針

Pull Requestで実行する。

```text
npm ci
npm run build
npx playwright install --with-deps chromium
npm run test:e2e
```

初期CI対象はChromiumだけとする。WebKit系はmainブランチ、手動実行、定期実行のいずれかで確認する。

失敗時はGitHub Actions artifactとして以下を保存する。

* Playwright HTMLレポート
* スクリーンショット
* trace
* 動画

README用画像の自動コミットは行わない。画像更新はローカルで実行し、差分を確認してコミットする。
