# requirements.md

# 不動産価格予測システム 要件定義書

## 1. 概要

中古マンションの予測価格を算出するWebアプリケーションを開発する。

本プロジェクトは不動産価格予測を題材として以下を実践することを目的とする。

* 機械学習
* システム設計
* データエンジニアリング
* 特徴量設計
* モデル運用

学習済みモデルをブラウザ上で実行し、サーバーレスで動作する構成を採用する。

---

# 2. プロジェクト目的

## 主目的

* システム設計能力を向上させる
* 不動産価格予測を通じて機械学習を学ぶ
* 実際に利用可能なサービスを構築する

## 副目的

* ポートフォリオとして公開する
* 将来的な機能拡張の土台を作る
* 学習成果を可視化する
* 予測価格の根拠を過度に重くならない範囲で説明する

## データ取得

* 自動取得スクリプトを作成する
* 年指定取得をサポートする
* 全対象地域一括取得をサポートする

不動産取引価格情報の取得元は国土交通省 不動産情報ライブラリを利用する。

```text
https://www.reinfolib.mlit.go.jp/realEstatePrices/
```

現行モデルで使う最寄駅名と駅徒歩分を保持するため、学習用の不動産取引データは公式画面から取得したCSV/ZIPを主入力にする。ブラウザアプリから不動産情報ライブラリへ直接アクセスしない。

ショッピングセンター開業データの取得元は日本ショッピングセンター協会（JCSC）のオープンSC一覧表を利用する。

```text
https://www.jcsc.or.jp/sc_data/sc_open/sc_list
```

JCSCデータは学習側のcollect処理で取得し、HTMLのraw保存、正規化JSON保存、エラーログ保存を行う。

ブラウザからJCSCサイトへ直接アクセスしない。

JCSCページの構造変更、取得失敗、カラム不一致、解析不能値は警告またはエラーとして記録し、サイレントに欠損値へ置換しない。

駅別乗降客数の取得元は不動産情報ライブラリの国土数値情報（駅別乗降客数）APIを利用する。

```text
https://www.reinfolib.mlit.go.jp/ex-api/external/XKT015
```

API利用時はAPIキーを利用し、学習側のcollect処理から取得する。

ブラウザからXKT015 APIを直接呼び出さない。

XKT015データはタイル単位のraw GeoJSON、正規化済み路線駅JSON、駅グループ集約JSON、学習・分析用CSV、配信用軽量JSONを生成する。

APIキー、raw GeoJSON、正規化中間成果物はGit管理しない。

災害リスク情報は、学習側のcollect処理で取得・正規化し、価格予測モデルへ投入できる特徴量CSVとして管理する。

ハザードマップ表示は国土交通省・国土地理院の「重ねるハザードマップ」ラスタタイルを利用する。ブラウザでは公開タイルの重ね合わせ表示を行い、出典表記を明示する。

指定地点の災害リスク判定は、ブラウザから外部APIへ直接アクセスせず、学習・前処理側で生成した正規化済みデータを利用する。

ハザード特徴量は、洪水、土砂災害、津波、高潮のリスクレベル、浸水深、データ有無を中心に設計する。価格モデルへ投入する場合は、ベースラインとのバックテストで二重評価や地域差によるノイズを確認してから採用する。

モデル説明機能は、ブラウザ推論の軽さを優先し、初期段階では学習側で生成した特徴量重要度またはSHAP集計を利用する。ブラウザ上でTreeSHAPを完全再計算しない。詳細は `docs/model-explainability.md` に記載する。

## 文字コード

国交省データは Shift_JIS を想定する。

システム内部では UTF-8 に統一する。

# 6. 出力仕様

## 予測結果

* 予測価格
* 平米単価
* 信頼区間

## 価格推移

### 過去価格推移

学習データを集計して表示する。

学習データ全件をブラウザへ配布せず、学習時に生成した集計済みJSONを利用する。

集計単位

* 年単位
* 最寄駅単位

### 将来価格予測

ユーザー指定年に対して予測を行う。

将来予測は参考値であり、精度保証は行わない。

学習データ範囲内の予測は transaction_year を特徴量として学習したモデルの結果を利用する。

学習データ範囲外の将来年は、LightGBM が年特徴量をそのまま外挿できないため、学習最終年のモデル予測値を基点に、駅別または地域別の価格推移トレンドで補正する。

この補正は将来価格の参考表示であり、価格上昇率モデルとして精度保証するものではない。

学習データの最新年から10年を超える予測年では警告を表示する。

将来価格をシミュレーション機能へ拡張する場合は、弱気、横ばい、標準、強気などのシナリオ別参考レンジとして表示する。詳細は `docs/future-price-simulation.md` に記載する。

# 8. 特徴量拡張方針

特徴量は FeatureProvider パターンで管理する。

将来的な追加候補

* 商業施設情報
* 駅情報
* 路線情報
* 人口統計情報
* 再開発情報
* 地理情報

商業施設情報については以下の特徴量を想定する。

* 周辺施設件数
* 最寄施設距離
* 近隣で直近に開業したSC件数
* 最寄SCまでの距離
* 最寄SCの開業からの経過年数
* 周辺SCの店舗面積合計
* 周辺SCのテナント数合計

商業施設情報は追加時点では候補特徴量として扱い、モデル比較で効果を確認してから採用する。

ノイズになりやすい特徴量、欠損や表記ゆれの影響が大きい特徴量、ブラウザ推論時に同等の値を再現しにくい特徴量は採用しない。

画面表示はモデル採用とは分けて扱う。初期表示では、市区町村単位のSC件数、直近開業SC、店舗面積合計など、JCSCデータから安定して生成できる参考情報を表示候補にする。緯度経度付与が安定するまでは、最寄SC距離や地図マーカー表示は必須にしない。

初期採用候補は次の通りとする。

* 物件取引年以前に開業済みの周辺SC件数
* 物件取引年以前に開業済みの最寄SC距離
* 物件取引年以前に開業済みの最寄SC開業後年数

店舗面積、テナント数、ディベロッパー、キーテナントは、欠損率と重要度を確認したうえで採否を判断する。

商業施設特徴量は未来情報の混入を避けるため、取引年より後に開業したSCを当該取引レコードの特徴量に利用しない。

駅別乗降客数については以下の特徴量を想定する。

* 最新乗降客数
* 対数乗降客数
* 乗降客数年度
* 乗降客数データ経過年数
* 駅規模ランク
* 乗り入れ路線数
* 運営会社数
* 駅徒歩を考慮した有効駅規模

駅別乗降客数は駅名カテゴリの情報を数値特徴量へ分解する目的で利用し、駅カテゴリを残すモデルと駅カテゴリを外した軽量モデルの両方で比較する。

ブラウザ推論ではAPIを呼ばず、学習側で生成した配信用軽量JSONを読み込む。

災害リスク情報については以下の特徴量を将来候補とする。

* 洪水浸水深最大値
* 洪水リスクレベル
* 土砂災害警戒区域フラグ
* 土砂災害特別警戒区域フラグ
* 津波浸水深最大値
* 高潮浸水深最大値
* 総合災害リスクスコア
* 災害リスク評価のデータ有無フラグ

災害リスク特徴量は初期段階では価格モデルに入れず、ユーザー向けの安全性指標として別表示する。モデル投入は、商業施設・駅規模特徴量と同じく候補特徴量として比較し、精度改善と配布サイズへの影響を確認してから判断する。

## MAE採用理由

利用者が知りたいのは平均して何万円程度の誤差が発生するかである。

MAEは価格予測において解釈しやすく、ユーザー価値との対応関係が明確であるため主要指標として採用する。
