# ハザード特徴量バックテスト候補

ハザード特徴量は、モデル成果物へ反映する前にベースラインと比較する。

初回比較では、2015年以降の取引データを中心に、既存特徴量へ段階的に追加して効果とノイズを確認する。

## 比較候補

| 候補 | 特徴量 | 目的 |
| --- | --- | --- |
| `baseline` | 既存特徴量のみ | 現行比較基準 |
| `hazard_available_flags` | `hazard_*_data_available`、`hazard_available_count` | データ有無自体が地域差ノイズにならないか確認 |
| `hazard_risk_levels` | 洪水、土砂災害、津波、高潮の `risk_level` | リスク区分の説明力を確認 |
| `hazard_depths` | 洪水、津波、高潮の `depth_max` | 浸水深の連続値が効くか確認 |
| `hazard_scores` | `hazard_overall_score`、災害別score | 総合スコア化した特徴量の安定性を確認 |
| `hazard_all` | 上記すべて | 最大構成の精度と過学習を確認 |
| `hazard_all_no_station` | `station` カテゴリなし + ハザード全特徴量 | 駅カテゴリ依存を減らした場合の代替可能性を確認 |

## 初回採用基準

* 2023年、2024年、2025年の時系列holdoutでMAEが安定して改善する
* 改善が一部地域だけに偏らない
* `hazard_*_data_available` の重要度が過度に高くならない
* ONNXとメタデータの配布サイズ増加が小さい
* ブラウザ推論の入力生成が単純に保てる

## 注意点

ハザード情報は、価格そのものではなく立地リスクの代理変数である。自治体ごとのデータ整備状況や都市部・沿岸部の偏りが強く出る可能性があるため、特徴量重要度だけで採用しない。

「区域外」と「データなし」は別の状態として扱う。欠損を単純に低リスクとして埋めると、未整備地域の価格傾向を誤って学習する可能性がある。
