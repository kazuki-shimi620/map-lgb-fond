# 用語集

この文書は、`map-lgb-fond`で使う技術用語を、自分の言葉で説明できるようにするための入門用資料です。
厳密な理論よりも「何か」「なぜこのアプリで使うか」「短くどう説明するか」を優先します。

## まず説明できるようにしたい用語

### KD-tree（ケーディーツリー）

ひとことで言うと、座標を近いもの同士に分けておき、最寄りの点を速く探すためのデータ構造です。

駅を毎回すべて調べる方法では、駅が増えるほど検索時間も増えます。KD-treeは空間を木構造に分割し、
明らかに遠い範囲を調べずに最寄駅を探します。このアプリでは緯度経度を単位球面上の3次元座標へ変換し、
駅マスタから最寄駅候補を探すために使っています。

説明するとき:

> 全国の駅を毎回総当たりせず、座標を木構造に整理して近い駅だけを効率よく探索しています。

### Haversine距離（ハーサイン距離）

ひとことで言うと、地球を球として扱い、2つの緯度経度間のおおよその直線距離を求める計算です。

平面上の距離計算ではなく地球の丸みを考慮します。このアプリではKD-treeで見つけた最寄駅と、
ユーザーが地図で選んだ地点との距離を求め、60mを徒歩1分として切り上げています。

説明するとき:

> 緯度経度から地球の丸みを考慮した直線距離を計算し、駅徒歩の目安へ変換しています。

注意点として、道路に沿った経路距離ではないため、川、線路、坂、横断歩道などは考慮しません。

### Overpass API（オーバーパスAPI）

ひとことで言うと、OpenStreetMapのデータから、条件に合う施設や道路を検索するためのAPIです。

例えば「日本国内の映画館」「指定範囲内の温泉」「`tourism=museum`の施設」のような条件で取得できます。
このアプリではブラウザから直接呼ばず、学習側で取得、キャッシュ、正規化した結果だけを配信しています。

説明するとき:

> OpenStreetMapから映画館や美術館など、必要な種類の地物だけを抽出する検索APIです。

注意点として、公開サーバーには負荷制限があり、大きな範囲を一度に要求すると504や429になることがあります。

### OpenStreetMap / OSM

世界中の利用者が共同で整備するオープンな地理データです。地図画像だけでなく、施設名、種別、道路、
建物などのデータも含みます。このアプリでは背景地図と、一部の周辺施設データに利用しています。

OSMの登録件数は実在する全施設数とは限りません。未登録、閉業後の残存、タグの表記差などがあるため、
coverageを示し、完全な施設台帳として扱わないことが重要です。

### Nominatim（ノミナティム）

OpenStreetMapのデータを利用した住所検索・逆ジオコーディングサービスです。

- ジオコーディング: 住所や駅名から緯度経度を求める
- 逆ジオコーディング: 緯度経度から住所を求める

このアプリでは地図検索や、選択地点の都道府県・市区町村取得に利用します。公開サービスには利用方針と
レート制限があるため、大量データ取得用途ではキャッシュや間隔制御が必要です。

## 地図・位置情報

### 緯度・経度（latitude / longitude）

- 緯度 `lat`: 南北の位置
- 経度 `lon` / `lng`: 東西の位置

GeoJSONでは座標順が `[経度, 緯度]` である一方、Leafletでは `[緯度, 経度]` を使う場面があります。
順序を間違えると全く別の場所になるため注意が必要です。

### GeoJSON

地点、線、ポリゴンなどの地理情報をJSONで表す標準的な形式です。施設なら`Point`、用途地域や
ハザード区域なら`Polygon`または`MultiPolygon`として表現できます。

### ラスタ

地図情報をピクセル画像として表す方式です。洪水浸水深の色付き画像などが該当します。
見た目をそのまま重ねやすい一方、画像だけから区域名や浸水深の数値を正確に取得するのは困難です。

### ベクタ

点、線、ポリゴンと属性データで地理情報を表す方式です。ラスタより構造を解析しやすく、
「この地点が区域内か」といった判定に向いています。

### XYZタイル

地図をズームレベル`z`、横位置`x`、縦位置`y`の小さな区画へ分割する方式です。
URLの`/{z}/{x}/{y}`へ値を入れると、その範囲の画像やGeoJSONを取得できます。

### bbox（バウンディングボックス）

対象範囲を囲む最小の長方形です。一般に南端・西端・北端・東端などで指定します。
Overpassの全国取得が重い場合、このアプリではbboxを小さく分割して再実行できるようにします。

### point-in-polygon

ある点がポリゴンの内側にあるかを判定する処理です。物件代表座標が用途地域やハザード区域に
含まれるかを調べる場合に使います。

### coverage（カバレッジ）

対象データのうち、実際に値を取得・対応できた割合です。例えば対象駅の82%に乗降客数を結合できた場合、
coverageは約82%です。精度が高くてもcoverageが偏っていると、地域そのものを暗黙に学習する危険があります。

## 機械学習

### 特徴量（feature）

モデルが価格を予測するために受け取る入力値です。面積、築年数、駅徒歩、市区町村、用途地域などが
該当します。モデルへ追加するだけでは価値があるとは限らず、同じ評価条件で精度を比較します。

### 目的変数（target）

モデルが予測したい正解値です。このアプリでは中古マンションの取引価格です。

### LightGBM（ライト・ジービーエム）

多数の決定木を順番に組み合わせて予測する機械学習ライブラリです。表形式データに強く、数値と
カテゴリを含む不動産データを扱いやすいため採用しています。

説明するとき:

> 面積や築年数、駅、市区町村などの条件分岐を多数組み合わせて価格を予測するモデルです。

### 決定木

「面積が60㎡以上か」「築年数が10年未満か」のような条件分岐を繰り返して予測するモデルです。
LightGBMは1本の木ではなく、多数の木を組み合わせて誤差を少しずつ補正します。

### FeatureProvider

特徴量を追加・生成する処理を、特徴量の種類ごとに分離するこのプロジェクトの設計方式です。
駅規模や地価などを独立したProviderとして実装し、学習パイプライン本体の変更を抑えます。

### 学習データ・検証データ・テストデータ

- 学習データ: モデルが規則を学ぶデータ
- 検証データ: パラメータ選択や途中評価に使うデータ
- テストデータ: 最後の性能確認だけに使う未知データ

同じデータで学習と評価をすると、実際より良く見えてしまいます。

### holdout（ホールドアウト）

一部のデータを学習に使わず、評価用に残す方法です。このアプリでは将来の取引を予測する状況へ近づけるため、
2023年、2024年、2025年などを評価年として分ける時系列holdoutを使います。

### baseline（ベースライン）

改善前の基準モデルです。新しい特徴量を追加したモデルが本当に良いか、同じデータ分割・指標で比較します。

### MAE

予測価格と実際の価格の差を絶対値にし、その平均を取った指標です。MAEが500万円なら、平均すると予測が
実価格から約500万円ずれているという意味です。小さいほど良い指標です。

### RMSE

大きな誤差をMAEより強く重く見る指標です。高額物件などで極端に外していないかを確認するのに役立ちます。
小さいほど良い指標です。

### MAPE

実価格に対する誤差の割合を平均した指標です。MAPEが20%なら、平均的な相対誤差が約20%という意味です。
ただし実価格が小さいデータの影響を受けやすい点に注意します。

### 時点リーケージ

予測時点では知り得なかった未来の情報が学習データへ混ざることです。現在の施設位置を過去の取引へ付与すると、
当時まだ開業していなかった施設を使ってしまう可能性があります。精度が良く見えても実運用では再現できません。

### 過学習

学習データへ合わせすぎて、未知のデータでは精度が落ちる状態です。複数年・複数地域のholdoutで改善が
再現するかを確認するのは、過学習や偶然の改善を見抜くためです。

### ハイパーパラメータ

木の数、木の深さ、学習率など、学習前に設定する値です。モデルがデータから直接学ぶ値とは区別します。

### Optuna（オプチュナ）

ハイパーパラメータの候補を効率よく試すためのライブラリです。このアプリでは精度だけでなく、木の本数や
モデル容量が過度に増えないことも考慮します。

### SHAP（シャップ）

各特徴量が予測値をどちらへどの程度動かしたかを説明する方法です。モデル全体の特徴量重要度とは異なり、
個別予測の理由を説明できます。ただしブラウザで完全計算すると重いため、学習側での集計を検討しています。

## ブラウザ推論・フロントエンド

### ONNX（オニキス）

異なる機械学習ライブラリや実行環境の間でモデルを受け渡すための共通形式です。Pythonで学習したLightGBMを
ONNXへ変換することで、JavaScript向けにモデルを作り直さずブラウザで実行できます。

### ONNX Runtime Web

ONNXモデルをブラウザで動かすライブラリです。このアプリでは予測APIサーバーを使わず、ユーザーのブラウザ内で
価格を計算するために利用しています。

### WebAssembly / WASM（ワズム）

ブラウザ上で高速な処理を行うためのバイナリ形式です。ONNX Runtime Webの推論処理に使われます。
JavaScriptだけで数値計算するより高速に実行しやすいのが利点です。

### React

画面を状態に応じて部品単位で組み立てるJavaScriptライブラリです。フォーム、地図、予測結果、グラフなどを
コンポーネントとして管理します。

### TypeScript

JavaScriptへ型の仕組みを加えた言語です。データ形状や関数の受け渡し間違いを、実行前に見つけやすくします。

### Vite（ヴィート）

フロントエンドの開発サーバーと本番ビルドを担当するツールです。TypeScriptやReactをブラウザで配信できる
ファイルへまとめます。

### Leaflet（リーフレット）

ブラウザへ地図を表示し、マーカー、タイル、ポップアップ、地図操作などを扱うライブラリです。

### クラスタリング

近い位置にある多数のマーカーを、件数付きの1つの円へまとめる表示方法です。このアプリではズームアウト時の
描画負荷を抑え、施設密度を見やすくするために使います。価格モデルのクラスタリング手法とは別物です。

### E2Eテスト

ブラウザを実際に操作し、入力から結果表示までをまとめて確認するテストです。このアプリではPlaywrightを使い、
地図、予測、グラフ、レスポンシブUIなどを確認します。

### Playwright（プレイライト）

ChromiumやWebKitなどを自動操作するブラウザテストツールです。画面操作、表示内容、スクリーンショット、
ブラウザ警告の確認に利用しています。

## データ処理・運用

### CSV / JSON / Parquet

- CSV: 表形式で、人が確認しやすい
- JSON: 階層構造を持てて、ブラウザで扱いやすい
- Parquet: 型を保持した列指向形式で、大量の表データを高速・省容量で処理しやすい

このアプリでは、公式CSVを前処理してParquetへまとめ、ブラウザ配信用には必要項目だけをJSONへ出力します。

### raw / processed / artifact

- raw: 取得したままの元データ
- processed: 正規化・結合・変換した中間データ
- artifact: モデルやメタデータなど、処理によって生成された成果物

rawとprocessedの大容量データはGit管理せず、ブラウザ実行に必要な最新成果物だけを`frontend/public`へ置きます。

### キャッシュ

一度取得・計算した結果を保存し、同じ処理を繰り返さない仕組みです。外部APIの負荷、処理時間、失敗時の
再取得範囲を減らします。

### dry-run（ドライラン）

本番処理を実行する前に、対象件数、要求数、出力先などを確認する試運転です。大量API取得や長時間学習を
いきなり開始しないために使います。

### metadata（メタデータ）

データそのものを説明するデータです。モデルの学習期間、評価指標、特徴量順、生成日時、coverageなどを
記録し、どのモデル・データを配信しているか確認できるようにします。

### CI/CD

- CI: 変更ごとにビルドやテストを自動実行する仕組み
- CD: 合格した成果物を公開環境へ自動配信する仕組み

このアプリではGitHub Actionsでビルドとテストを行い、`main`へ反映されたフロントエンドをGitHub Pagesへ
デプロイします。

### サーバーレス / 静的配信

このアプリの「サーバーレス」は、価格予測用の常駐APIサーバーを持たず、モデルとJSONを静的ファイルとして
配信する構成を指します。ただし地図、住所検索、ハザードタイルなど、一部の外部サービス通信はあります。

## 30秒でプロジェクトを説明する例

> 国土交通省の中古マンション取引データをLightGBMで学習し、ONNXへ変換してブラウザ内で価格を予測するアプリです。地図で選んだ地点からKD-treeで最寄駅を高速検索し、Haversine距離を駅徒歩の目安へ変換します。周辺施設はOpenStreetMapのOverpass APIなどから事前収集し、軽量JSONとして配信しています。モデル更新は年度holdoutでMAE・RMSE・MAPEを比較し、改善が再現した特徴量だけを採用します。
