# 周辺特徴量追加方針

本ドキュメントは、商業施設・駅規模・ハザード以外の周辺特徴量を追加する場合の候補、採用基準、実装順を定義する。

地価公示・基準地価、人口統計、用途地域、学区、保育園、路線利便性、犯罪・治安などの取得スクリプト設計は `docs/data-source-acquisition.md` で管理する。

## 目的

中古マンション価格に影響しうる生活利便性や地域特性を、ブラウザ推論の容量と速度を壊さない範囲で特徴量化する。

## 基本方針

初期実装では、地点ごとの大量POIをブラウザへ配布しない。

学習側で距離や件数を集計し、LightGBMへ入れる特徴量だけを保持する。

```text
外部データ
↓
学習側で正規化
↓
取引地点または自治体単位へ集計
↓
特徴量CSV
↓
LightGBM
```

フロントエンドで同じ特徴量を再現できないものは、モデルへ採用しない。ブラウザ推論時に必要な場合は、駅マスタと同じく軽量JSONへ圧縮して配布する。

## 候補と優先度

| 候補 | 初期優先度 | 理由 |
| --- | --- | --- |
| 大型公園 | 高 | 距離・面積で集計しやすく、生活環境の説明に使いやすい |
| 病院 | 中 | 利便性指標として有効な可能性があるが、施設種別の定義が必要 |
| 大学 | 中 | 学生需要や賃貸市場には効きやすいが、中古マンション価格では地域差の代理になりやすい |
| 再開発エリア | 低 | 価格への影響は大きい可能性があるが、時系列と境界定義が難しい |

## 初期特徴量案

### 大型公園

候補:

```text
nearest_large_park_distance_km
large_park_count_within_1km
large_park_count_within_3km
large_park_area_sum_within_3km
has_large_park_data
```

面積しきい値を設け、小規模な街区公園を大量に拾わない。

### 病院

候補:

```text
nearest_hospital_distance_km
hospital_count_within_3km
large_hospital_count_within_5km
has_hospital_data
```

診療所と病院を混ぜない。初期は病床数や救急指定などの品質差を入れず、件数と距離だけで比較する。

### 大学

候補:

```text
nearest_university_distance_km
university_count_within_3km
university_count_within_5km
has_university_data
```

所在地がキャンパス単位で取れる場合のみ距離特徴量にする。法人本部所在地だけのデータは使わない。

### 再開発エリア

候補:

```text
redevelopment_project_count_city
redevelopment_project_count_last_5y
nearest_redevelopment_distance_km
has_redevelopment_data
```

初期は自動収集よりも手動マスタを優先する。計画発表、着工、竣工のどの時点から特徴量として効かせるかを明確にし、未来情報の混入を避ける。

## 採用基準

採用する特徴量は次を満たす必要がある。

* 2025年ホールドアウトまたは時系列バックテストで安定して改善する
* 欠損フラグだけが重要度上位にならない
* データの更新方法を説明できる
* 地域差そのものの代理変数になりすぎない
* ブラウザ配信用メタデータが大きく増えない

改善が数万円程度に留まる場合は、モデルを複雑にしないため採用しない。

## 実装順

1. 大型公園を市区町村単位または距離集計で試す
2. 病院を施設種別を絞って試す
3. 大学をキャンパス単位データが安定する場合だけ試す
4. 再開発エリアは手動マスタで小さく試す

## モデル比較

既存の外部特徴量比較と同じく、ベースライン、単独追加、組み合わせ追加を比較する。

```text
baseline
large_park
hospital
university
large_park_hospital
external_all
```

商業施設、駅規模、ハザードと同時に入れる場合は、特徴量同士が同じ地域差を重複して拾っていないか確認する。

## 非目標

初期段階では次を行わない。

* POIデータをそのままブラウザへ配布する
* 施設名をカテゴリ特徴量として大量に投入する
* 施設レビュー、口コミ、混雑度など変動しやすい情報を使う
* 再開発の将来期待だけで長期価格保証のように表示する
